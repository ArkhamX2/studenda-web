# Описание клиентского приложения (frontend)

Веб-клиент реализован на базе React, TypeScript и Material UI. Приложение предназначено для работы с расписанием, посещаемостью и управлением учебным процессом для трёх ролей: студент, преподаватель, администратор. Вся навигация построена на React Router.

## Основные компоненты и структура

- **App.tsx** — корневой компонент, где настраивается роутинг, провайдеры авторизации и настроек, глобальная тема.
- **AuthProvider, SettingsProvider** — контекстные провайдеры для авторизации и пользовательских настроек.
- **UserHeader, AdminHeader** — шапки для разных ролей с меню и навигацией.
- **FullSchedule, TodaySchedule, DaySchedule** — компоненты для отображения расписания (на неделю, на день, на сегодня).
- **AccountProfile** — компонент профиля пользователя.
- **EntityListPage, EntityListItem** — универсальные компоненты для списков и карточек сущностей (пользователи, группы, дисциплины и т.д.).

## Роутинг и основные страницы

### Общие маршруты
- `/` — домашняя страница, перенаправляет пользователя в зависимости от роли.
- `/login` — страница авторизации.
- `/change-password` — смена пароля при первом входе или по требованию.

### Для студента
- `/student` — главная страница студента (сегодняшние занятия).
- `/student/schedule` — полное расписание студента.
- `/student/account` — профиль студента.
- `/student/day/:date/:weekTypeId/:dayPositionId/:year` — детальный просмотр дня.

### Для преподавателя
- `/teacher` — главная страница преподавателя (сегодняшние занятия).
- `/teacher/schedule` — полное расписание преподавателя.
- `/teacher/account` — профиль преподавателя.
- `/teacher/day/:date/:weekTypeId/:dayPositionId/:year` — детальный просмотр дня.
- `/teacher/journal/:subjectId` — журнал посещаемости по занятию.

### Для администратора (панель управления)
- `/admin` — корневой маршрут панели, содержит боковое меню и вложенные страницы.
- `/admin/user` — список пользователей.
- `/admin/user/edit/:id?` — создание/редактирование пользователя.
- `/admin/role` — список ролей.
- `/admin/role/edit/:id?` — создание/редактирование роли.
- `/admin/course` — список курсов.
- `/admin/course/edit/:id?` — создание/редактирование курса.
- `/admin/group` — список групп.
- `/admin/group/edit/:id?` — создание/редактирование группы.
- `/admin/department` — список факультетов.
- `/admin/department/edit/:id?` — создание/редактирование факультета.
- `/admin/discipline` — список дисциплин.
- `/admin/discipline/edit/:id?` — создание/редактирование дисциплины.
- `/admin/subject` — список занятий (расписание).
- `/admin/schedule/subject/edit/:id?` — создание/редактирование занятия.
- `/admin/subject-position` — позиции учебных предметов.
- `/admin/subject-position/edit/:id?` — создание/редактирование позиции.
- `/admin/week-type` — типы учебных недель.
- `/admin/week-type/edit/:id?` — создание/редактирование типа недели.
- `/admin/subject-type` — типы учебных предметов.
- `/admin/subject-type/edit/:id?` — создание/редактирование типа предмета.
- `/admin/day-position` — позиции учебного дня.
- `/admin/day-position/edit/:id?` — создание/редактирование позиции дня.

## Краткое описание работы

- После авторизации пользователь попадает на главную страницу своей роли.
- Студент и преподаватель видят расписание на сегодня, могут перейти к полному расписанию или детальному дню.
- Преподаватель может отмечать посещаемость в журнале.
- Администратор управляет пользователями, учебными сущностями и расписанием через панель.
- Все страницы используют защищённые маршруты (RequireStudent, RequireTeacher, RequireAdmin).
- Данные загружаются через REST API с сервера, отображаются в виде таблиц, карточек и календарей.

## Подробное описание работы клиентского приложения

Клиентское приложение обеспечивает интуитивно понятный и адаптивный интерфейс для всех ролей пользователей. Основные сценарии работы реализованы с учетом удобства и безопасности.

### Авторизация и маршрутизация
- При первом входе пользователь проходит авторизацию. В зависимости от роли (студент, преподаватель, администратор) происходит автоматическое перенаправление на соответствующую главную страницу.
- Все защищённые маршруты реализованы с помощью компонентов RequireStudent, RequireTeacher, RequireAdmin, которые не допускают неавторизованных пользователей к закрытым разделам.

### Работа студента
- На главной странице студент видит приветствие, дату и список занятий на сегодня с деталями (время, предмет, преподаватель, аудитория).
- Можно перейти к полному расписанию на неделю или к детальному просмотру дня.
- В профиле отображается личная информация, группа, курс, факультет.

### Работа преподавателя
- Преподаватель видит аналогичную страницу с расписанием на сегодня, но только для своих занятий.
- В разделе "Журнал" преподаватель может отмечать посещаемость студентов, видеть список студентов группы, отмечать прогулы и комментарии.
- Доступен просмотр полного расписания и детализация по дням.

### Работа администратора
- Администратор управляет всеми сущностями: пользователями, ролями, группами, курсами, факультетами, дисциплинами, занятиями и параметрами расписания.
- Для каждой сущности реализованы страницы списка, создания и редактирования. Все действия сопровождаются валидацией и подтверждением.
- Панель администратора выполнена в виде отдельного layout с боковым меню и быстрым доступом к основным разделам.

### Общие особенности
- Все данные загружаются и обновляются через REST API. При изменении данных происходит автоматическое обновление интерфейса.
- Используются современные компоненты Material UI для обеспечения единого стиля и адаптивности.
- Для работы с датами и неделями используется библиотека dayjs.
- Приложение поддерживает работу на мобильных устройствах и планшетах.
- В случае ошибок или отсутствия данных отображаются информативные сообщения.
- Для повышения производительности реализовано кэширование некоторых данных на клиенте.

### Безопасность и UX
- Все формы защищены от некорректного ввода, реализована валидация на клиенте.
- При выходе из системы происходит сброс сессии и перенаправление на страницу входа.
- В интерфейсе используются всплывающие уведомления и подтверждения для критичных действий (например, удаление сущностей).

### Развёртывание и поддержка
- Приложение собирается в production-режиме и развёртывается в Docker-контейнере.
- Вся статика обслуживается через Nginx, а API-запросы проксируются на backend.
- Структура кода и компонентов позволяет легко расширять функционал и добавлять новые разделы.
